# Security model

Sift is a local-first desktop application with approval-gated provider mutations. Its security boundary assumes the Windows user account and operating system remain trusted.

## Desktop boundary

- The Electron renderer is sandboxed and context-isolated, has no Node.js integration, and receives a closed schema-validated preload bridge.
- IPC handlers reject calls outside Sift's exact application origin.
- Popups, foreign navigation, renderer permissions, remote network fetches, webviews, object/frame content, raw email HTML rendering, and inline/evaluated scripts are blocked.
- Provider OAuth uses the system browser, PKCE, and loopback callbacks. Proton uses credentials generated by the local Proton Mail Bridge, not the Proton account password.
- Refresh tokens and Bridge credentials are encrypted with Electron `safeStorage` and never enter the renderer after connection.

## Mail safety

- Address ownership comes only from provider identity evidence, Sent-folder `From` evidence, or supported direct-delivery evidence. Arbitrary recipients and group participants cannot become owned identities.
- Existing external rules are inventoried and protected. Sift changes only rules it manages or exact rules the user approves for adoption.
- Historical mutations use immutable plans, live preconditions, post-write verification, durable receipts, selective retry, and provider-state-aware Undo.
- Spam is routed only through provider-native Spam or Junk. Sift never contacts suspected spam through an unsubscribe endpoint.
- Cleanup uses provider-native recoverable Trash or Deleted Items. Sift implements no permanent provider-mail deletion.

## Local data and recovery

- Generated profile IDs—not display names—form local paths, and each profile uses a separate SQLite database and secret namespace.
- Content-free diagnostics expose counts and health status only.
- Encrypted backups authenticate the complete payload and are intended for the same Windows user and device. Restore validates the target profile, checksums, database schema, integrity, relationships, and secret-file set before replacement.
- A local-index rebuild preserves connections, managed-rule ownership, and unsubscribe history while removing downloaded metadata and derived analysis.

See [Recovery and maintenance](RECOVERY.md) for operational details.

## Reporting a vulnerability

Do not put credentials, tokens, addresses, message content, private diagnostic data, or exploitable details in a public issue. Open a minimal GitHub issue requesting a private maintainer contact path. Content-free Sift diagnostics can be reviewed locally before sharing.
